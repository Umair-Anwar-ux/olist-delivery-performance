# Power BI report

The dashboard is `delivery_reviews.pbix`. The data is stored inside the file, so it opens and works straight away in Power BI Desktop without a refresh.

The other files in this folder:

- `pbip/` holds the same report as plain text files (a Power BI Project: the data model in TMDL and the report layout in PBIR). This makes the report readable and comparable in Git. It is generated by `scripts/build_powerbi_project.py`.
- `measures.dax` is a readable copy of all 34 DAX measures, generated from the same definitions as the model.
- `olist_theme.json` is the colour theme: blue for on-time orders and volume, orange for late orders, grey for order status.

I built and tested it with Power BI Desktop version 2.158.1304.0 (September 2026), installed with `winget install --id Microsoft.PowerBI --source winget`, which runs Microsoft's own installer. The Microsoft Store version failed to install on my machine with error 0xc8000444.

## Pages

1. Business Overview: total orders, delivered orders, late-delivery rate, average review score, delivered order value (in reais, not profit), monthly orders and late rate, and order value by region.
2. Delivery Operations: filters for purchase date, customer region, product category and seller; late rate by customer state; shipping routes, sellers (at least 100 delivered orders) and categories (at least 500) ranked by excess late orders; and the median time for each step, on time against late.
3. Customer Experience: the spread of review scores, review scores on time against late, how many late-order reviews were written before delivery, late rate and review score by region and category, and the share of canceled or unavailable orders over time.
4. Metric Definitions: tables of key totals that should match the SQLite build, and a plain-language explanation of each metric. Every measure also has its definition attached as a description, which shows when you hover over it in the Data pane.

Images of every page are in the [screenshots](../screenshots/) folder. They were made from Power BI's own PDF export (File, then Export, then Export to PDF), which is saved as [reports/delivery_reviews_dashboard.pdf](../reports/delivery_reviews_dashboard.pdf).

## Data model

```
dim_date      --> fct_orders <==> fct_order_items <-- dim_product
dim_customer  --> fct_orders                      <-- dim_seller
                  fct_orders  --> fct_payments
```

- `fct_orders` has one row per order, `fct_order_items` one row per item, and `fct_payments` one row per payment.
- Order measures count rows in `fct_orders`. The relationship between orders and items filters in both directions, so the category, seller and route filters select whole orders and each order is counted once.
- Flags such as `is_late` come from SQLite as 1 or 0, and a blank means "not applicable". Measures test for `= 1`, or use the strict `== 0`, so a blank is never counted as on time.
- Three calculated columns are added: `Delivery Outcome` (late, on time, or not counted) and `Review Stars` on `fct_orders`, and `Lane` (seller state to customer state) on `fct_order_items`.

The metrics follow the same definitions as the SQL (`sql/04_business_analysis.sql` and `docs/methodology.md`). That includes the calendar-date rule for late deliveries and a separate measure for the stricter timestamp rule.

## Opening the report

Double-click `powerbi/delivery_reviews.pbix`. Power BI Desktop runs on Windows. No sign-in or refresh is needed.

## Refreshing after rebuilding the data

1. Run `python scripts/build_database.py`. This rewrites the CSV files in `data/processed` from the SQLite database.
2. In Power BI Desktop, click Home, then Refresh.
3. If the project folder has moved, first update the CSV location: Home, Transform data, Edit parameters, then set DataFolder to the full path of `data\processed\` (keep the backslash at the end).
4. Save the file.

## Rebuilding the .pbix from the source files

```bash
python scripts/build_database.py              # SQLite build and CSV exports
python scripts/build_powerbi_project.py       # regenerate the files in powerbi/pbip
python scripts/powerbi_automation.py build    # open in Power BI, refresh, export PDF and images, save the .pbix
```

The last script clicks through Power BI Desktop for you (using pywinauto), so leave the computer alone while it runs. To do it by hand: open `pbip/delivery_reviews.pbip`, click Refresh now (and Apply changes if asked), export to PDF, then use File, Save as, Browse this device, choose "Power BI file (*.pbix)" as the file type, and save it as `powerbi/delivery_reviews.pbix`.

If you pass `--schemas <folder>` to `build_powerbi_project.py`, it checks every report file against the JSON schemas that ship with Power BI Desktop before writing it. I extracted those schemas from the Power BI Desktop install folder (`bin\WebView2Resources\minerva\scripts\desktop.schema.json.*.min.js`).

## Checking the report against the SQL results

```bash
python scripts/powerbi_automation.py verify --adomd <path>\Microsoft.AnalysisServices.AdomdClient.dll
```

This opens `delivery_reviews.pbix` and connects to the data model that Power BI Desktop is running in the background. It calculates 38 DAX expressions and compares each one with `reports/headline_metrics.json` from the SQLite build. The results are written to [reports/powerbi_reconciliation.md](../reports/powerbi_reconciliation.md), and all 38 match.

The connection needs Microsoft's ADOMD.NET client library. It is in the NuGet package `Microsoft.AnalysisServices.AdomdClient.retail.amd64`: download the `.nupkg` file from nuget.org, unzip it (it is a zip file) and use the DLL in `lib/net45`.
