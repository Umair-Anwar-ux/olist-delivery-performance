# Power BI report

| File | What it is |
|---|---|
| `delivery_reviews.pbix` | **The report.** Power BI Desktop file with the data embedded: open it and it works without refreshing. |
| `pbip/delivery_reviews.pbip` | Text source of the same report (Power BI Project): TMDL semantic model + PBIR report definition. Diff-able in Git; generated by `scripts/build_powerbi_project.py`. |
| `measures.dax` | Readable copy of all 34 DAX measures (generated from the same definitions as the model). |
| `olist_theme.json` | Report theme (blue = on time / volume, orange = late, grey = status). |

Built and tested with **Power BI Desktop 2.158.1304.0 (September 2026)**, installed with
`winget install --id Microsoft.PowerBI --source winget` (Microsoft's official installer; the Microsoft Store
package `9NTXR16HNW1T` failed on the build machine with error `0xc8000444`).

## Pages
1. **Business Overview**: total orders, delivered orders, late-delivery rate, average review score, delivered order value (BRL, not profit), monthly order volume and late-rate trend, value by region.
2. **Delivery Operations**: slicers for purchase date, customer region, product category and seller; late rate by customer state; shipping lanes, sellers (≥ 100 delivered orders) and categories (≥ 500) ranked by excess late orders; median lifecycle stage durations, on time vs late.
3. **Customer Experience**: review-score distribution, review score on time vs late, the review-timing caveat (share of late-order reviews written before delivery), late rate and review score by region and category, canceled + unavailable trend.
4. **Metric Definitions**: reconciliation tables (totals that must equal the SQLite build) and plain-language definitions. Each measure also carries its definition as a description (hover it in the Data pane).

Screenshots of every page are in [`../screenshots/`](../screenshots/). They are rendered from Power BI's own *File → Export → Export to PDF* output ([`../reports/delivery_reviews_dashboard.pdf`](../reports/delivery_reviews_dashboard.pdf)).

## Data model

```
dim_date ──────► fct_orders ◄════► fct_order_items ◄── dim_product
dim_customer ──►     │                     ▲
                     ▼                     └────────── dim_seller
               fct_payments                 (_Measures: measure table)
```

* Grain: `fct_orders` = 1 row per order; `fct_order_items` = 1 row per order item; `fct_payments` = 1 row per payment record.
* Order measures count rows of `fct_orders`. The `fct_orders ↔ fct_order_items` relationship filters **both directions**, so category, seller and lane slicers select whole orders and each order is counted once.
* Flags (`is_late`, `is_delivery_kpi_eligible`, ...) are 1/0 integers exported from SQLite; blank means "not applicable". Measures test `= 1` or use strict `== 0`, so a blank is never counted as "on time".
* Calculated columns: `fct_orders[Delivery Outcome]` (Late / On time / Not in delivery KPI), `fct_orders[Review Stars]`, `fct_order_items[Lane]` (seller state -> customer state).

The metric definitions are the same as the SQL layer (`sql/04_business_analysis.sql`, `docs/methodology.md`), including the **calendar-date late rule** and the **timestamp-rule sensitivity** measure.

## Open the report
Double-click `powerbi/delivery_reviews.pbix` (Power BI Desktop, Windows). No sign-in or refresh is needed.

## Refresh after rebuilding the data
1. `python scripts/build_database.py` rewrites `data/processed/*.csv` from the SQLite database.
2. In Power BI Desktop: **Home → Refresh**.
3. If the project folder moved, first set the CSV folder: **Home → Transform data → Edit parameters → DataFolder**, using the full path to `data/processed\`, including the trailing backslash.
4. **File → Save**.

## Rebuild the .pbix from source
```bash
python scripts/build_database.py              # SQLite build + CSV exports
python scripts/build_powerbi_project.py       # regenerate powerbi/pbip (TMDL + PBIR)
python scripts/powerbi_automation.py build    # open, refresh, export PDF + screenshots, save .pbix
```
The automation clicks through Power BI Desktop with `pywinauto`, so leave the machine alone while it runs. To do it by hand: open `pbip/delivery_reviews.pbip`, click **Refresh now** (then **Apply changes** if prompted), **File → Export → Export to PDF**, then **File → Save as → Browse this device → Save as type: Power BI file (*.pbix)** → `powerbi/delivery_reviews.pbix`.

`build_powerbi_project.py --schemas <dir>` validates every report JSON file against the PBIR JSON schemas shipped inside Power BI Desktop. On the build machine they were extracted from `bin\WebView2Resources\minerva\scripts\desktop.schema.json.*.min.js`.

## Verify the report against the SQL results
```bash
python scripts/powerbi_automation.py verify --adomd <path>\Microsoft.AnalysisServices.AdomdClient.dll
```
This opens `delivery_reviews.pbix`, connects to the model Power BI Desktop is hosting (local Analysis Services port from `msmdsrv.port.txt`), evaluates 38 DAX expressions and compares each with `reports/headline_metrics.json` from the SQLite build. The result is written to [`../reports/powerbi_reconciliation.md`](../reports/powerbi_reconciliation.md).
The ADOMD.NET client is Microsoft's NuGet package `Microsoft.AnalysisServices.AdomdClient.retail.amd64` (`lib/net45`); download the `.nupkg` from nuget.org and unzip it (it is a zip file).
